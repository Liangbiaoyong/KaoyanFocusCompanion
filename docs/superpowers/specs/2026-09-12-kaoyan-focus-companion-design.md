# 考研专注养成扩展 · 设计文档

日期：2026-09-12
状态：待评审

## 1. 背景与目标

使用者是一名考研备考生，日常学习**全部发生在 Edge 浏览器内**：主要看 PDF（本地与网页），也会看网课、查资料。

核心痛点是**走神分心**，四种形式并存：切到其他网页/标签页、拿起手机、发呆、坐不住不想开始。

目标是做一个**只属于自己的** Edge 扩展，让"保持专注"这件事有即时反馈和长期积累，从而愿意持续投入。明确**不做**硬拦截式监工（"严师模式"被否决），采用**养成模式**。

手机分心是浏览器扩展覆盖不到的部分，本文档不处理，另行解决。

## 2. 核心设计原则

1. **测量必须诚实**。养成类工具最大的失败模式是"空心化"——PDF 挂着、人不在，成长值照涨。两三天后使用者就不信它了。所以计分条件必须严格。
2. **惩罚落在"最该被惩罚的时刻"**。惩罚只在"人坐在电脑前、学习标签开着、却在干别的"时触发；使用者真生病、没开电脑时，扩展不运行，不记时也不扣分。
3. **阶段可升可降，但升级容易、掉级需要持续懈怠**（使用者明确选择"可掉级"）。因单次超时只扣 10 分钟、而阶段间隔为几到几十小时，掉级必然源于持续多日的懈怠，不会因一个下午的状态差发生。
4. **默认"中性"而非"敌对"**。未分类站点只暂停计时，不记录、不评价。避免使用者每开一个查资料页面都要配置，也避免扩展整天摆出"在抓你"的姿态。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 成长值 | 决定凤凰阶段的账户数值。初始为 0，随专注累加，被惩罚削减。可下降。 |
| 累计专注 | 真实累计的专注时长，只增不减。用于统计与"山"的进度。 |
| 精神值 | 0–100 的今日状态值，每天重置。只影响凤凰当天的表情，不决定阶段。 |
| 学习标签 | 当前被判定为"学习内容"的标签页。 |
| 专注段 | 从进入 FOCUSING 状态到退出的一个连续区间。 |

## 4. 测量引擎

### 4.1 计分条件

以下三条**同时满足**才走表：

1. 活动标签是学习内容（见 4.2）
2. Edge 窗口拥有系统焦点（`windows.onFocusChanged` / 非最小化）
3. 距上次键鼠输入不超过 **10 分钟**（看门狗阈值，可配置）

任一条不满足即暂停。

### 4.2 站点三档

| 档位 | 判定 | 行为 |
|---|---|---|
| 学习 | 命中 `siteRules.study` | 计分 |
| 中性（默认） | 未命中任何规则 | 暂停，不记录、不评价 |
| 分心 | 命中 `siteRules.distract` | 暂停，走神次数 +1，精神值下降 |

`siteRules.study` 默认内置：`file:///*.pdf`、`*://*/*.pdf`（URL 路径以 `.pdf` 结尾，忽略查询串）。
未分类站点一律为中性；使用者可在设置页把任意站点标为学习或分心。

**已知局限**：不以 `.pdf` 结尾的 PDF（知网、arXiv `/pdf/1234` 等）与网课页面无法自动识别，需要手动标记。

### 4.3 状态机

状态：`IDLE` / `FOCUSING` / `PAUSED_AWAY` / `PAUSED_DISTRACTED` / `WAITING_ACTIVITY`

| 当前 | 事件 | 迁移 | 副作用 |
|---|---|---|---|
| 任意 | 学习标签在前台 ∧ Edge 有焦点 | `FOCUSING` | 记 `startedAt`、`lastActivityAt` |
| `FOCUSING` | 键鼠输入 | `FOCUSING` | 刷新 `lastActivityAt` |
| `FOCUSING` | 距 `lastActivityAt` > 看门狗阈值 | `WAITING_ACTIVITY` | 成长值 −10 分钟；精神值 −20 |
| `FOCUSING` | 活动标签变为分心站点 | `PAUSED_DISTRACTED` | 走神次数 +1；精神值 −5 |
| `FOCUSING` | 活动标签变为中性站点，或 Edge 失去焦点 | `PAUSED_AWAY` | 无（仅结算） |
| `WAITING_ACTIVITY` | 键鼠输入 ∧ 条件恢复 | `FOCUSING` | 重置 `lastActivityAt` |
| `PAUSED_*` | 条件恢复 | `FOCUSING` | 重置 `lastActivityAt` |

任一迁移都先**结算**：把 `[lastSettledAt, now)` 区间按当前状态计入（仅 `FOCUSING` 计正分），并更新 `lastSettledAt`。

### 4.4 结算与跨天

- 计时以**时间戳差**为准，不依赖 tick 频率。
- 结算时把增量秒数记入**当时所属日期**的 bucket，跨天自动正确。
- 每日 **00:00（本地时区）** 结算：写当日 `daily` 记录，重置 `todayFocusSeconds` 与精神值。
- 每日计入上限 **8 小时**（可配置）：超出部分 `todayFocusSeconds` 仍增长（如实显示），但不再进入成长值与精神值。

### 4.5 计时实现要点（MV3 关键约束）

MV3 的 service worker 会被浏览器随时回收，**不能依赖常驻的 `setInterval`**。

- 所有时间戳（`startedAt` / `lastActivityAt` / `lastSettledAt`）持久化到 `chrome.storage.local`。
- 用 `chrome.alarms` 每分钟唤醒一次做"结算 + 超时检查"；用事件（`tabs.onActivated`、`tabs.onUpdated`、`windows.onFocusChanged`、`idle.onStateChanged`）做即时响应。
- worker 被唤醒时，按时间戳**补算**休眠期间经过的时间。

## 5. 养成系统

### 5.1 凤凰 12 阶段

阶段由**成长值**决定。单位：累计专注小时。

| 阶段 | 名称 | 阈值 |
|---|---|---|
| 1 | 蛋 | 0h |
| 2 | 裂纹蛋 | 0.5h |
| 3 | 雏鸟 | 2h |
| 4 | 幼鸟 | 6h |
| 5 | 学飞 | 14h |
| 6 | 飞鸟 | 26h |
| 7 | 彩羽 | 44h |
| 8 | 灵鸟 | 70h |
| 9 | 火羽鸟 | 105h |
| 10 | 半凰 | 150h |
| 11 | 火凰 | 210h |
| 12 | 凤凰 | 300h |

曲线意图：头一两天进化两次（新手快感），之后逐步拉长（长期拉力）。300 小时约等于每天 5 小时、连续两个月，对考研周期是合适的量级。

**掉级**：成长值跌破当前阶段下限即退化一级，可连续退化。升级时给出庆祝反馈，掉级时给出明确的、不带羞辱意味的提示（凤凰"掉回了上一层营地"）。

**阶段 12 之后**：阶段不再变化，山的进度继续推进至考试日。凤凰在登顶时是"凤凰"，不再有更高的形态。

### 5.2 山（目标锚点）

- 设定**考试日期** `examDate` 与**每日目标时长** `dailyGoalMinutes`（默认 5 小时）。
- 起算日 `startDate` = 首次引导当天。
- 剩余天数 `N` = max(1, 考试日 − 今天)；总天数 `D` = max(1, 考试日 − 起算日)。`max(1, …)` 用于避免考试当天除零——考试当天视为"还剩最后一天的配额"。
- 目标总时长 `T` = `N × dailyGoalMinutes`。
- 时间进度 `p_time` = 已过天数 ÷ `D`；你的进度 `p_you` = 累计专注 ÷ `T`。
- 落差 `Δ = (p_you − p_time) × T`，即"**领先 / 欠 X 小时**"。
- 两条进度线均截断到 `[0, 1]` 显示，避免超出画面。

侧边栏在山的图形上画**两条线**：一条时间线、一条你的线。山不是装饰，它每天回答"我进度够不够"。

### 5.3 精神值（今日轨）

0–100，每日 00:00 重置为 50。

- `FOCUSING` 中每专注 2 分钟 +1（上限 100）
- 超时 −20
- 走到分心站点 −5
- 下限 0（凤凰"蔫了"，但**不影响阶段**）

### 5.4 连续天数

达标日 = 当日计入时长 ≥ `dailyGoalMinutes`。

- 连续达标则 `streak` 递增，未达标则中断归零。
- 每月提供 **2 张补签卡**，自动替未达标的一天补签，保持连续。

（此为提案；如实际过于严苛或过于宽松，调整阈值即可，不影响架构。）

## 6. 界面

### 6.1 侧边栏（主界面）

布局：**场景融合式（B）**，画风：**清冷山系（B）**——雾蓝灰、小圆角、细线、多留白。

- 一整块山景，凤凰站在"你当前海拔"的位置
- 山巅有旗（= 考试日），场景内标注"海拔 / 距考试 N 天"
- 山下信息区：今日计时（大字）、今日目标完成度、凤凰名 + 精神值条、连续天数、累计时长
- 两条进度线叠加在山景上（时间线 vs 你的线）

### 6.2 设置页

考试日期、每日目标时长、每日计入上限、看门狗阈值、凤凰名字、站点三档管理（学习 / 分心列表的增删与切换）。

### 6.3 统计页

- 每日专注时长趋势（折线/柱状）
- 走神热点：按时间段与站点的走神次数分布
- 累计专注、达标天数、最长连续

### 6.4 首次引导

设定考试日期 → 每日目标 → 给凤凰起名 → 引导开启"允许访问文件网址"权限 → 展示侧边栏打开方式。

## 8. 架构

MV3 扩展，按"纯逻辑核心 + 浏览器外壳"分层：

```
src/
  core/            # 纯函数，不依赖任何浏览器 API，可单元测试
    engine.js      # 状态机与结算
    growth.js      # 阶段、精神值、山的计算
    sites.js       # 站点三档分类与 URL 匹配
  background/
    service-worker.js   # 事件订阅、alarms、读写 storage、广播
  sidepanel/       # 侧边栏 UI
  options/         # 设置页
  stats/           # 统计页
  lib/
    storage.js     # storage 读写封装
    messaging.js   # 消息/订阅封装
manifest.json
```

- 后台是唯一的状态所有者；UI 只读。
- 后台结算后写 `storage`，各 UI 通过 `chrome.storage.onChanged` 订阅并重绘。简单可靠，不引入额外状态同步复杂度。
- 全部数据本地，不联网，不上传。

## 9. 技术风险与验证步骤

**步骤 0：在写任何功能之前先验证以下四点。**

1. **能否读到 `file:///` 本地 PDF 的活动标签 URL。** 需要使用者在扩展详情页开启"允许访问文件网址"。
   - 若不可行，退路：(a) 使用者把 PDF 拖入扩展自带的阅读页（方案 B 缩水版）；(b) 改为手动"开始专注"按钮。
2. **Edge 是否支持 `chrome.sidePanel`**，以及侧边栏的尺寸与常驻行为。
3. **`chrome.idle` 的检测精度**，以及 10 分钟阈值下的误判率。
4. **MV3 service worker 被回收后计时是否连续**（等 worker 被回收后观察补算是否正确）。

> 本文档撰写时网络受限，以上四点均未实际验证，全部按"待验证假设"处理。

## 10. 测试策略

- `core/` 三个模块是纯函数，用单元测试覆盖：三条件切换、10 分钟超时扣分、跨天结算、每日上限、掉级边界、阶段阈值边界、站点匹配、山的进度计算。
- `background/service-worker.js` 只做事件接线与持久化，逻辑尽量下沉到 `core/`，保证薄。
- UI 手动验证（侧边栏渲染、设置页、统计页、首次引导）。
